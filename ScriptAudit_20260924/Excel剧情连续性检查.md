# Excel 剧情连续性检查

检查日期：2026-09-24。范围：ExcelVNScripts 目录下当前 43 个 XLSX、第一工作表的 3570 个剧情节点。只检查表格；CSV 不作为本报告依据。不修改任何剧本。

方法：全量核对 ID、命令括号、jump / loadScript 目标、选项目标、Note 标签及 wherelist、隐藏控制行层级、章节末尾；按照项目现有隐藏分支选择规则进行默认开场的静态路径模拟。没有运行 Unity，也不验证音画资源、存档或远程资源加载。

项目规则：选择按钮本身不记录同名剧情标签；标签由节点 Note 的 tag= 写入。隐藏控制行在后续下一层候选中选第一个匹配条件，未匹配时使用无条件候选或同级后续节点；均不存在时到达剧本末尾。因此“文字写了选项名称”不等于“设置了条件标签”。

以下“行”均为 Excel 行号，ID 为 A 列剧情 ID，K 列为 Command，L 列为 Note。

## 结论

发现 8 类会造成剧情中断、失去预期出口或循环的问题，另有 2 处命令括号错误和 3 处条件逻辑隐患。当前表格按默认开场、空剧情标签模拟，两条主线都存在前置断点，未到达结局。这个结论仅指当前表格和现有条件执行规则，不代表已经逐路线实机游玩。

## 1. 大卫线“追问 / 忽视”标签从未写入

- 上游：sntzm_david313-315(1).xlsx，ID 42，K39，选项跳到 ID 46（行 41）或 ID 45（行 67）。两个落点的 Note 均没有 tag=追问 / tag=忽视；全体表格也没有写入这两个标签。
- 确定断点：sntzm_david313-315(2).xlsx，ID 45，行 46。仅有 ID 46 的“追问=1”和 ID 47 的“忽视=1”，没有兜底或同级出口。无论上游选哪个，都不能匹配。
- 后续同类断点：sntzm_david313-315(3).xlsx，ID 40，行 39，仍要求这两个标签。
- 复现示例：开场“不是”→“接听无线电”→“与大卫随行”→“就此作罢”，推进到 (2) 的 ID 45 后停止。
- 修复方向：在对应选择的落点明确记录标签，并统一后续条件名称。

## 2. 克拉克线错误跳入大卫线

- sntzm_clark4F(2).xlsx，ID 28 / 91，K39 / K64，均为 loadScript(sntzm_david4F(3), 1)。
- 两行 Note 的 gotomainline 均写“克拉克线4层（下）_1”，与 Command 不符。
- 大卫目标章节 ID 2（行 3）只接受“无视飞蛾（大卫） / 端详飞蛾（大卫） / 立刻离开”。正常克拉克路线不具备这些标签，跳过去后无法匹配，剧情停止。
- 根据目标章节标题和 Note，预期目标应核对为 sntzm_clark4F(3), 1。
- 复现示例：开场“不是”→“接听无线电”→“跟上克拉克”→“询问了关于艾米丽的问题”→“开枪故意射偏”→“这一定有什么古怪”，随后经 clark4F(2) ID 91 进入 david4F(3) ID 2 后停止。

## 3. “深入探究 / 视为陷阱”标签从未写入

- sntzm_david3F(1).xlsx：ID 19（行 19）、28（行 26）、33（行 30）、67（行 59）、83（行 74）、98（行 94）均依赖这两个标签，没有兜底。
- 玩家在 david3F(1) ID 12 选择“仔细端详飞蛾”，会在 ID 19 中断；选择“装作无事离开”，会在 ID 98 中断。

- 这些是前置断点修好之后仍会出现的问题。修复方向是补齐相应选项落点标签，并确认 david313-315(6) 的二次选择是否也应设置或更新同一组标签。

## 4. 大卫 313–315 第五章缺少结尾续接

- sntzm_david313-315(5).xlsx，ID 69，行 66，K66 为空，是本表最后一行。
- 前一章的“视为陷阱”分支会 loadScript 到本章 ID 3；推进完广播和营救对话后到达 ID 69，既不是结局，也没有跳转下一章。
- ID 31 的第一个选项从 ID 34 走到 ID 50 后，还会顺序进入另一选项所在段落，最后同样到 ID 69 停止。
- 修复方向：明确两段选项的汇合/离开位置，补充剧情设计所要求的后续章节。不能仅凭文件编号判断应该接到 (6) 还是 david3F(1)。

## 5. 克拉克第四层终章使用了大卫专属条件

- 子分支 ID 72（行 33）要求“端详飞蛾（大卫）=1 且 立刻离开=0”；ID 93（行 54）要求“无视飞蛾（大卫）=1 或 立刻离开=1”。

- 修复方向：按克拉克线是否与索菲亚同行的实际设计，核对并替换条件。

## 6. 终局选择未记录标签，终局6无法匹配

- ID 53 / 54（行 98 / 99）只有跨表跳转，Note 没有对应 tag。全部表格也没有写入“选择大卫”“选择亚波伦”。

## 8. 真结局跳到已不存在的 ID 17

- sntzm_truth(3).xlsx，ID 38，K35：jump(17)，本表没有 ID 17。
- 当有“无视飞蛾（克拉克） / 无视飞蛾（大卫） / 立刻离开”任一标签时，ID 37 控制点会选中 ID 38。
- 跳转失败后若继续顺序推进，会进入 ID 3 → 10 → 11 → 12 → jump(5)，之后又经 ID 37 回到 ID 38，形成循环，无法走到结局 ID 40。
- 核对缺失的 ID 17 是否需要恢复；如果已经删掉该段，应确认是否改接现存 ID 18，不应未经剧情确认直接修改。

## 命令语法风险：两处多余右括号

1. sntzm_clark4F(4).xlsx，ID 92，K53：loadScript(sntzm_final(3), 8))，尾部多一个右括号。ID 8 本身存在，问题是命令字符串语法，而非缺少 ID 8。Note 还写“终局（上）_1”，目标意图也应一并核对。
2. sntzm_david4F(4).xlsx，ID 44，K42：parallel(memoryon();bgfade(sntzm_david313-315(2)_33,1)))，多一个右括号。

具体表现取决于命令解析器对多余括号的容错，不能只凭表格断言一定硬卡死，但应修正后再同步。

## 另外三处条件逻辑隐患

- sntzm_clark4F(3).xlsx：ID 2 的条件仅要求“无视飞蛾（克拉克）=1”，位于更具体的 ID 3 之前。ID 3 要求同一标签加“夜莺线、不开枪”，因此通过本章 ID 1 控制点时总会先匹配 ID 2，ID 3 被遮挡。
- sntzm_gy(s1).xlsx：ID 96，L97，OR 条件中使用“无视飞蛾（克拉克）=0”。这会使不少本来有索菲亚的路线也跳到无索菲亚脚本；需要确认 0 是否应为 1。这是走错分支风险，不能仅凭这一行判定卡死。
- 同表 ID 98，L93，OR 条件重复写了两次“无视飞蛾（克拉克）”，没有“无视飞蛾（大卫）”。建议核对第二项是否复制错了标签。

## 检查边界与建议顺序

未发现空 ID、重复 ID、选项 jump 目标缺失、wherelist JSON 无法解析或当前引擎不支持的条件比较格式。全量 jump / loadScript 检查已经覆盖所有表，不因某章从开场暂时不可达而跳过。

先修复 1、2 两个前置阻断，再修复 3–8 的后续断点，最后处理括号和条件逻辑隐患。完成表格修正后再同步 CSV，并实机验证主要选择组合。对于章节结尾和缺失的 ID 17，需依据剧情意图决定正确接点。
